# Internationalization (i18n)

Externalize is bilingual (English / French). Locales are **not** a translation layer.

## Principle

Each locale is written as it would appear in that language's university logic course:

| | English | French |
|---|---------|--------|
| Tradition | Introductory / analytic logic | Logique propositionnelle |
| Examples | Yale-style course notes | Sorbonne-style cours |

**Parity of pedagogy, not parity of wording.**

## File layout

```
src/i18n/
  locale.ts      — preference load/save
  messages.ts    — exercise prompts, feedback, practice UI
  lessons.ts     — Level 0 course copy, reference panel, learn UI
  index.ts       — exports
```

Each file holds **parallel `en` and `fr` objects**. There is no translation function, no shared source string, no `t('key')` lookup from a master catalog.

## Vocabulary reference

### English

- sentence letter, atomic formula
- truth assignment / interpretation
- main connective, scope, subformula
- conjunct, disjunct, antecedent, consequent
- material conditional, biconditional
- evaluates to T / F

### French

- variable propositionnelle, formule atomique
- interprétation, valuation
- connecteur principal, portée, sous-formule
- arguments (of a connecteur)
- implication matérielle, équivalence
- vrai / faux; labels **V** / **F**

## Adding new content

1. Add the lesson or exercise definition (language-neutral) in `src/app/`.
2. Add **both** `en` and `fr` entries in the appropriate `src/i18n/*.ts` file.
3. Write each locale's copy from scratch.
4. Extend `src/i18n/*.test.ts` to assert both locales have the new keys.

## Switching locale at runtime

The app re-renders with the selected locale's strings. Formulas (`P ∧ Q`, etc.) stay symbolic — only surrounding prose changes.
